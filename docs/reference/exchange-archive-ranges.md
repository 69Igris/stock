## Why the three earlier guesses 404'd

`AttachLive/{XML_NAME}.xml`, `AttachHis/{XML_NAME}.xml` and
`AnnualReport/{XML_NAME}.xml` are one mistake, not three: **`XML_NAME` is not a
filename.** The announcement's attachment field is `ATTACHMENTNAME` (a bare
GUID `.pdf`), and BSE's own site builds that link as
`/xml-data/corpfiling/AttachLive/{ATTACHMENTNAME}` (live) or
`/xml-data/corpfiling/CorpAttachment/{YYYY}/{M}/{ATTACHMENTNAME}` (archived).
The guessed **directory** was right; the **field** was wrong — which is exactly
why they returned 404 rather than a redirect or a 403.

## The `200 with no rows` rule — where it held and where it misled

The registry's standing rule (`exchange-registry-verification.json`, on
`bse-index-daily-all`) is that a plausible path returning no rows is a **params**
problem and the path must not be re-derived. Both outcomes happened here:

- **It HELD** for `GetCorXbrlDetails_ng`, which answers
  `{"Error":[{"message":"From Date and To Date are mandatory."}]}` — an
  endpoint stating its own contract. Supplying the dates was the whole fix.
- **It MISLED** on `Corpforthresults`, whose name means *forthcoming* results —
  a board-meeting calendar. An empty body there is a truthful "nothing
  scheduled", not a wrong param set. A name that reads as "corporate results"
  and means "results not yet filed" will keep a probe hammering a
  correct-and-useless endpoint indefinitely.

## The index defect, and why the fix is a fallback

Integrated-era **NBFC** rows are indexed into the **legacy** `NBFCUploadDocument`
directory and 404. Every other integrated family is indexed into an
`IF*UploadDocument` directory and serves. Separating **directory** from
**filename prefix** is what made the cell visible — one dimension alone reads as
"that directory is broken" or "recent filings are unfetchable", and both are
wrong:

| directory `::` filename prefix | result |
| --- | --- |
| `FourOneUploadDocument :: Main_Ind_As_*` | 200 · `in-bse-fin` 2020-03-31 |
| `FourOneUploadDocument :: NonBanking_*` | 200 · `in-bse-fin` 2018-03-31 |
| `NBFCUploadDocument :: NBFC_*` | 200 · `in-bse-fin` 2019/2020-03-31 |
| `IFIndasUploadDocument :: Integrated_Finance_Ind_As_*` | 200 · `in-capmkt` 2026-01-31 |
| `IFOtherthanUploadDocument :: IFOtherthan_*` | 200 · `in-capmkt` 2025-01-31 |
| **`NBFCUploadDocument :: Integrated_Finance_NBFC_*`** | **404 — the only failing cell** |

So it is **not** the directory (`NBFC_*` serves from the same one), **not** the
era (two other integrated families serve), **not** recency (Jan-2026 integrated
files for 519421 and 532351 serve), and **not** the filer sector alone (legacy
NBFC files serve). The files are at `IFNBFCUploadDocument` — verified **6/6**
across three NBFCs (512437, 539773, 530127) and both `in-capmkt` versions. Two
other sibling spellings 404, so that directory is specific, not a catch-all.

`bseInstanceUrlCandidates()` applies this as a **fallback** — indexed URL first,
rewrite only on failure — so the two futures stay distinguishable: if BSE fixes
the index, recoveries fall to zero; if BSE moves the sibling, **failures** rise
instead. A blind rewrite would sail through the first and go silent through the
second. It is a **workaround for a BSE defect, not a durable fact about their
layout** — re-test before deleting it. The segment is matched
case-insensitively (IIS), and the rewrite is narrowed to the
`Integrated_Finance_NBFC_` prefix because the same directory's legacy files
serve fine and a directory-wide rewrite would break them.

## Identity — the sentinel that is not an absence

A BSE-only issuer files `<in-capmkt:Symbol>NOTLISTED</in-capmkt:Symbol>`. It is
a **literal sentinel, present in the document**, not a missing field.
`XbrlFiling`'s unique key is
`symbol + exchange + periodEnd + periodType + basis + cumulative`, so a writer
that accepts any non-empty symbol collapses **every** BSE-only issuer for a
given quarter and basis onto one row, where they overwrite each other — a
cross-company merge presenting as a working ingest with a low row count. Hence
the scrip-code bridge (`resolveWritableSymbol`): `InstrumentMapping.bseScripCode`
first, then ISIN, and a counted refusal rather than a guess. Dual-listed filers
(RELIANCE) state a real symbol and never reach it.
