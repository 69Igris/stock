## Build (flag `us-stocks-listing` for the section; per-broker flags per the SnapTrade plan; paid plans + founder allowlist only per the cost-control decision)
1. **`/brokers` gains a US section** "Bring your US accounts in. Read-only, as always." with status line "● 4 INDIA BROKERS · US ◷ EOD · JUL 18 CLOSE" and two cards ordered by persona (NRI: Link first; LRS: Import first). Link card: broker grid (Robinhood · Fidelity · Schwab · Webull · E*TRADE + "More brokers · 20+ VIA SNAPTRADE" → full list from the P18 broker registry with per-broker flag + "approval-gated" tags), read-only copy line, "US data disclosure" link (W12). Import card: format tags + drop zone.
2. **Consent → portal → sync → done:** consent screen (broker tile → U mark, "via SnapTrade", WHAT HAPPENS NEXT steps, scopes table, "REVOKE ANY TIME · SETTINGS › MARKET PREFERENCES", "Continue to {Broker} →") → SnapTrade connection portal (`connectionType: "read"`, `customRedirect` back to `/api/brokers/snaptrade/callback`) → "Syncing your US accounts" progress (positions · lots · transactions counts as the job reports them; px/fx provenance lines; "You can leave — we finish in the background. Skip ahead →") → done card ("{N} ACCOUNTS CONNECTED · {positions} positions, in." + `DualCurrency` total + tags ◷ EOD · SPOT · READ-ONLY; "See mixed holdings →" / "Open AAPL") → failure/re-auth state ("{Broker} needs re-authorising — SnapTrade reports the broker session expired on {date} — normal for this broker. Your other accounts synced fine." + "Re-authorise →" / "Remind me tomorrow"; `BrokerReauthBanner` pattern app-wide). Webhook `CONNECTION_BROKEN/FIXED` drives the state.
3. **Statement import wizard** (`/brokers/import-us` or `/tradebook/import?market=us`, reusing the tradebook import shell): Step 1 upload (CSV/PDF ≤ 20 MB; format hints; parsed card "vested_apr26.csv · 184 KB · 42 ROWS · READ OK · PARSED"), Step 2 column mapping (auto-detected Vested/INDmoney/Schwab/IBKR/generic; per-column confidence; editable; "Extra columns are kept, not dropped"; row issues panel — missing FX → "Use RBI rate · ₹x" (computed from the RBI ref for that date) / "Enter it"; unknown symbol suggestions from `UsInstrument` search ("BRK.B " → BRK-B); flagged rows never block), Step 3 review & commit (new lots vs duplicates skipped — dedupe against existing lots with the same hash logic; table with RBI REF ON TRADE + COST; totals via `DualCurrency`; "Commit N lots →"; LRS persona: "ALSO UPDATED — Your LRS headroom → adds $12,400 to FY26-27" → W11). Re-import must be obvious ("Imported before? We de-duplicate against your existing lots.").
4. **Provenance & FX rules (Decision 02):** every US price shows `DelayedDataBadge`; values use spot (`getUsdToInr`, stamp "SPOT ₹84.00/$ · 1H"); cost basis and every LRS figure use the RBI reference rate of the trade date (`getRbiReferenceRate`; if unavailable → `RbiRateUnavailableError` → the row is flagged "needs FX", never silently filled with spot). FX stale > 24 h → `DataGapBanner` on converted totals.
5. **Vendor never named in UI copy** except the consent screen's "via SnapTrade" (the portal is theirs); price provenance says "third-party consolidated tape".

## Data wiring
- SnapTrade (from P18): `packages/core/src/brokers/snaptrade/*` client + `BrokerConnection` rows per SnapTrade account (`broker: SNAPTRADE_ROBINHOOD` …), `POST /api/brokers/snaptrade/connect` (portal URL) + `/callback` (status=SUCCESS&connection_id) + webhook route (HMAC `Signature`), sync worker mapping positions → `Holding{currency:"USD", exchange:"NASDAQ|NYSE", market:"US"}`, activities → `Trade` lots with `fxRateOnTrade` (RBI ref) — polling limits per the plan (≤ 4 background holdings calls/day/user; activities ≤ 1/account/24 h). Auto-delete disabled connections > 30 days (email day 23).
- Import: extend `format-detector.ts` + `column-mappings.ts` with `VESTED`, `INDMONEY`, `SCHWAB_PDF` (via document-process OCR → table), `IBKR_ACTIVITY_CSV`, `GENERIC_US`; required fields `trade_date, symbol, trade_type, quantity, trade_price, currency, fx_rate_on_trade?`; `row-parser` gains `currency`/`fxRateOnTrade`; dedupe hash includes currency; pairing (`packages/core/src/pairing`) must treat USD lots as USD (FIFO unaffected; no Indian tax computed on US lots — W11 note).
- Actions: `startUsConnectAction(broker)`, `getUsConnectionsAction`, `reauthUsConnectionAction`, `revokeUsConnectionAction`, `previewUsStatementAction(file)`, `commitUsStatementAction(batch)` (async via the existing import job + progress), `getUsImportHistoryAction`.
