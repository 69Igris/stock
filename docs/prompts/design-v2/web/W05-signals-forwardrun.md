## Build (under `strategies-v2`)
1. **Signals tab (per strategy, unlocked at ≥ BACKTESTED):** "SCHEDULE & ALERTS" card = `AlertSignalConfig` labels="signals": schedule EOD 16:05 IST (default) / INTRADAY (PRO; 15-min cadence during NSE hours), channels Push · Email digest · WhatsApp (PRO, disabled with tag until a WhatsApp provider exists — do not stub sends), quiet hours, min-match threshold; master on/off toggle. RECENT SIGNALS list (status pill · symbol · rule text · time · price · sparkline) → signal detail sheet (1M chart with entry marker at trigger price, "THE RULE THAT FIRED" plain English + "Values at trigger: RSI(14) = 34.2 · volume 2.8× 20-day avg · above 200 DMA. This is an observation from your strategy's rules — what you do with it is up to you.", buttons "Ask Sage about {sym}" (prefill) / "Alert config"). Empty: "No signals yet — first scheduled run is tonight, 16:05 IST."
2. **Global Signals feed** (W03 tab) now reads real rows; the topbar bell gets `NotificationType` `SIGNAL_TRIGGERED` (push + in-app), `BACKTEST_DONE`, `FORWARDRUN_DIVERGENCE`.
3. **Signal engine (`workers/src/processors/signal-eval.ts`):** Cloud Scheduler → Pub/Sub `signal-eval` at 16:05 IST weekdays (and PRO intraday cadence); for each active signal watch: run the strategy DSL over the latest bars with the same `LocalEngine` kernels (backtest/live parity — same code path, golden-tested), emit `Signal` rows NEW/TRIGGERED, expire after N sessions (EXPIRED), respect `cooldownMinutes`, fan out via `notifications.service` + `packages/email` digest. Missed runs are recorded as gaps (never interpolated). Idempotent on Pub/Sub redelivery (key `strategyId+symbol+barDate`).
4. **TradingView webhook** (Settings → Integrations, or the strategy's Signals tab "Pipe TradingView alerts"): per-user URL `https://hooks.usemoney.ai/tv/{userToken}?sig=HMAC` — implement as `apps/web/app/api/webhooks/tradingview/route.ts` (public route pattern; HMAC-SHA256 over body with a per-user secret stored encrypted via `packages/security`), reveal/rotate secret, "Send test ping" (server-side self-ping proving signature verification), last-5-pings log (`WebhookPing` model or embed in `Alert.conditions` — choose a model), bad signature → 401 logged. Ingested alerts become `Signal` rows with source `TRADINGVIEW`.
5. **Forward Run tab (unlocked at FORWARD):** "SHADOW PORTFOLIO — SINCE {date}" · "SIMULATION — NO REAL ORDERS" · stats (HYPOTHETICAL P&L · NIFTY SAME PERIOD · VS BACKTEST BAND with `divLabel`) · curve vs NIFTY · LEDGER — HYPOTHETICAL FILLS, COSTS IN (rows: symbol · side qty @ in → out · P&L · OPEN) · KV (Started · Divergence checks NIGHTLY · Alerts · Execution COMING LATER) · divergence card ("Inside the band — behaving as tested." / amber outside 1σ, red beyond 2σ) · disabled "Execute for real" seam. Promotion: `promoteToForwardRunAction` (VALIDATED only) creates `ForwardRun` and flips status to FORWARD; "Retire" ends it.
6. **ForwardRun engine (`workers/src/processors/forwardrun-valuation.ts`, nightly after EOD):** consumes TRIGGERED signals → hypothetical fills at next session open (+ cost model), appends `ForwardRunTrade` rows (append-only), values open lots at close, computes pnlPct vs NIFTY, annualised live CAGR vs the backtest band (band = latest `Backtest` CAGR ± 1σ from walk-forward folds), sets divergence, notifies on band exit. Reproducible from fixtures.
7. **Language cleanup this module owns:** user-facing "paper trading" retired per the ForwardRun decision — `/paper-trading` stays flag-gated/hidden, nav copy and demo data updated, root `CLAUDE.md` feature list + tier table updated; grep-proven "no remaining user-facing 'paper trading' strings" (demo data included).

## Data wiring
- Actions: `getStrategySignalsAction`, `upsertSignalWatchAction` (writes `Alert{kind:"STRATEGY_SIGNAL", conditions:{strategyId, schedule, threshold}, notifyChannels}`), `getSignalDetailAction`, `getWebhookConfigAction`/`rotateWebhookSecretAction`/`testWebhookPingAction`, `promoteToForwardRunAction`, `getForwardRunAction`, `retireForwardRunAction`.
- Services: `packages/services/src/signals.service.ts` (+ `signals-logic.ts`: NEW/TRIGGERED/EXPIRED transitions, cooldown, gap recording), `forwardrun.service.ts` (+ `forwardrun-logic.ts`: fill model, valuation, divergence), `webhooks-tradingview.service.ts`.
- `apps/api` (inside `/v1/strategies` and `/v1/alerts`): `GET/PUT /v1/strategies/:id/signals/config`, `GET /v1/strategies/:id/signals`, `GET /v1/strategies/signals/:signalId`, `POST /v1/strategies/:id/forward-run`, `GET /v1/strategies/:id/forward-run`, `POST /v1/strategies/:id/forward-run/retire`, `GET /v1/alerts/webhooks/tradingview` (config, no secret in plain text beyond the reveal endpoint with re-auth).
- Push: emits through the notification fan-out; device push delivery itself is A01 (mobile API).

## Non-goals
Order execution (a deliberate disabled seam), intraday signals for FREE/PRO-less tiers, WhatsApp delivery.

## Acceptance
- Signal fires deterministically on fixture candles (same kernels as backtest — parity test), respects cooldown, and writes exactly one row per (strategy, symbol, bar) under redelivery.
- Webhook rejects a bad HMAC (401, logged), accepts a valid ping, test-ping shows latency + "SIGNATURE VALID"; secret rotation invalidates the old URL.
- ForwardRun valuation reproducible from fixtures; divergence WITHIN/HOT/COLD unit-tested at the band edges; ledger is append-only (test: no update/delete path exists).
- Simulation disclaimers rendered verbatim on every P&L surface; grep shows zero user-facing "paper trading".
