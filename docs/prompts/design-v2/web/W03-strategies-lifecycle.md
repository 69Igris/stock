## Current state
Catalog with hardcoded performance numbers and fake user counts; "Backtest" charges credits and shows static figures; Forward is a redirect to a tab; Custom builder + "Create AI" exist (`generateStrategyAction`); strategy "run" = a scan (`runStrategyAction` → `strategy-scan` worker → `ScanResult`). No lifecycle, no signals, no shadow portfolio. The quant engine (DSL, backtester with costs, CPCV/PBO, Deflated Sharpe) is a separate programme (`archive-docs/quant-prompts/02–05`) and is not in the repo.

## Decision for this build: UI now, engine-gated
Build the whole surface against a **`StrategyEngine` interface** in `packages/services/src/strategy-engine/` with two implementations: `LocalEngine` (TypeScript, real but bounded: multi-symbol daily backtest over `DailyPrice`/`Candle` with brokerage + STT + 5 bps slippage, equity curve vs NIFTY 50 from `IndexClose`, CAGR/Sharpe/max DD/win rate/turnover/costs paid/trades, walk-forward on fixed splits — promoted from `api/backtest/route-logic.ts`) and `RemoteEngine` (stub that returns `ENGINE_UNAVAILABLE` until `services/quant-engine` ships; carries Deflated Sharpe, CPCV/PBO, overfit level). Every screen renders honestly from whichever fields are present: missing → "validation unavailable until the quant engine ships" (never a number).
