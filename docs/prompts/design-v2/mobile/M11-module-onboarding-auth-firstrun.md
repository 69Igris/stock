## Build
1. **Public group `(public)`:** Splash (auto-advance, skips straight to the app when a Clerk session exists and the user has completed first-run) → Onboarding carousel (4 slides; visuals rebuilt in RN with the broker PNGs from `assets/brokers/`) → Welcome (hero + chips deep-linking into sign-up with the prompt remembered for the first Sage turn).
2. **Auth (Clerk):** Sign up (Google via `startSSOFlow`, Apple — **see M02 store-review note: enable Apple before iOS submission; render the button only when Clerk has the provider enabled**, email/password with the strength meter + terms line), Verify email (6-digit code, resend timer), Sign in (Google, Apple, phone, email/password, trust-device toggle → Clerk session length), Add phone + SMS code (optional step, skippable), 2FA (TOTP code + backup code link), Forgot → Reset (email code + new password), Invite claim (`/v1/…` — check `apps/web/app/api/invite/[token]/redeem` and add an API mirror if missing), SSO redirect screen (spinner while the session settles). Copy per design; `ClerkRow` footers; TradingView credit line where the design shows it.
3. **Post-sign-up:** poll `/v1/me` until the user exists (webhook lag), record terms acceptance (`POST /v1/me/terms`), then Investor profile (5 questions → verdict screen; writes `experienceLevel`/`riskAppetite`/goals via `PATCH /v1/me/preferences` + the W14 questionnaire endpoint when available; the verdict names map to persona presets Beginner → beginner, Explorer → intermediate, Pro → advanced).
4. **First run — connect:** broker list (8 India brokers from `BROKER_META`/`/v1/brokers/catalog` — add the catalog sub-path if the API lacks one), tap → **consent sheet** (scopes ALLOWED/NEVER, SEBI consent text → `POST /v1/consent`) → OAuth in an in-app browser (`expo-web-browser.openAuthSessionAsync(url, "usemoney://oauth/callback")`) where `url` comes from a new `POST /v1/brokers/:id/oauth-url { returnTo: "app" }` (mirror of `getOAuthUrlAction`) and the **web callback learns an allow-listed `returnTo=app` state that redirects to `usemoney://oauth/callback?broker=…&status=…`** (web change, small, in this ticket) → First sync progress driven by `GET /v1/brokers/sync-status` + `/v1/brokers/:id/counts` polling (steps advance on real milestones; never a fake timer) → Ready screen with real totals from `/v1/dashboard` ("12 HOLDINGS · 214 TRADES · 42 PAIRS").
5. **Skip paths:** "Skip — explore with demo data" → demo session (server-backed: add `POST /v1/demo/session` returning a demo JWT-less mode? — the web demo uses an HMAC cookie; for mobile implement demo as a **read-only demo user** the API serves when `X-Demo-Session` is present, or reuse `/api/demo/start` semantics — decide, document, and keep demo data identical to web); "or import a CSV" → M13 import wizard.
6. **Biometric unlock:** `expo-local-authentication` gate on cold start when enabled in Settings (M19), with passcode fallback; never blocks the public group.
7. **US fork:** when `us-stocks-listing` is on for the user, the connect screen shows "Invest in the US too?" → M20's fork screen; skipping keeps India defaults.

## Non-goals
Push permission prompt (M19 decides the moment), Settings, US link/import (M20).

## Acceptance
- New user: sign up with email → verify → profile → connect Zerodha (QA sandbox or a founder account) via the in-app browser → app returns on `usemoney://oauth/callback` → sync steps advance on real API milestones → Ready screen shows real counts; consent row exists in `/v1/consent`.
- Existing user: Google sign-in lands on Home in < 3 s on QA; 2FA path works with TOTP; password reset works end-to-end.
- Webhook-lag handling proven (test with a mocked 401 → 200 sequence); no "User not found" ever shown to the user.
- Demo mode shows the banner and identical demo numbers to web (contract test against the shared demo fixture).
- Apple button hidden when the provider is disabled; screenshots light/dark for every screen in this module; `verify:push`; `/code-review ultra` (auth + broker tokens).
