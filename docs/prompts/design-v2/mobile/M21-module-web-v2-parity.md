## Build
1. **Screener v2** (`/screener2`, reachable from Discover when W02 is live; else the Discover scans list stays): market `Seg` (flag; server-gated), one search box (ticker typeahead via `/v1/discover/search`; phrase → gold row → `POST /v1/screener/ai-filters` (W02's `generateFiltersFromThesisAction` mirror — add if missing) with `CreditChip` when non-zero), scans sheet from `GET /v1/scans` (merged rail: ENGINE | CHARTINK | STRATEGY | YOURS, counts or `—`, lock for gated), scan runs in place (`POST /v1/scans/:id/run` sync/async), context card with rule tags + edit-as-filters (draft state local; "Save as scan" → `POST /v1/saved-screens`), quick chips (India/US sets from the server universe metadata), results (cursor) with source tag; empty/degraded/gated states; "Track this scan as a strategy" → `POST /v1/strategies/from-scan` → detail.
2. **Strategies** (`/strategies`): tabs; catalog/custom lists from `GET /v1/strategies?tab=`, cards with real stats or the honest CTA (`CreditChip` = `strategy_backtest`), Signals feed from `GET /v1/strategies/signals` grouped Today/Earlier with strategy chips; "+ New" → Create AI sheet (describe → `POST /v1/strategies {source:"AI", prompt}` after the credit confirm) → detail (DRAFT).
3. **Strategy detail** (`/strategy/[id]?tab=`): from `GET /v1/strategies/:id`; lifecycle dots; Overview (plain rules, DSL sheet, stats or none, overfit warning only when the engine supplied a level, "See current matches" → screener with `?scan=strategy:{id}`); Backtest (`GET /:id/backtests/:latest` → growth-of-₹10,000 chart from the equity curve, validation rows or "validation unavailable until the quant engine ships"; "Run backtest ⚡" → config sheet (period/universe/cost preset) → `POST /:id/backtests` → progress → refresh); Signals (`GET/PUT /:id/signals/config` schedule + channels; recent signals; locked → teach copy); Forward run (`GET /:id/forward-run`; promote via `POST /:id/forward-run` when VALIDATED; ledger; divergence; simulation disclaimer verbatim; locked → teach copy).
4. **Settings → Developer** (`/devsettings`, PRO+ / allowlist per W13): keys list (`GET /v1/me/developer/keys`), create (name + scopes sheet → `POST` → one-time reveal with copy → "shown once"), revoke (`DELETE`), MCP config card (endpoint + selected key; copy; "Send test ping" → `POST /v1/me/developer/ping` → latency + tools count), usage (`GET /usage`), tool catalog (`GET /tools` with provenance badges), footer.
5. **View presets:** the screener/strategies read `viewPresets` from `/v1/me/preferences` for Beginner/Intermediate/Advanced density (Beginner = curated scans first, fewer chips; Advanced = everything) — same key as web (W00).

## Non-goals
Full filter sidebar on mobile, DSL editing/builder (web-only in v1; "Edit in builder" links to web), TradingView webhook setup (web-only).

## Acceptance
- Screener: a rail scan runs in place and renders the same symbols as the web screener for the same scan id on QA (contract test on `/v1/scans/:id/run`); AI phrase charges once; US pill absent when flag off.
- Strategies: catalog shows real backtest stats or the CTA; running a backtest on QA moves DRAFT → BACKTESTED and the detail refreshes; locked tabs show the teaching copy; simulation disclaimer present on Forward run.
- Developer: creating a key reveals it once; the test ping returns the real tool count; revoked key disappears from config.
- Presets persist through the shared key and match web.
- Screenshots (screener, strategies, detail ×4 tabs, developer; light/dark); `verify:push`; `/code-review ultra` (credits + keys).
